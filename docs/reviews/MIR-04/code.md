## Residual operational note

If the Admin API is unavailable throughout the bounded compensation window, the adapter correctly reports `RollbackIndeterminate`; callers must treat that as requiring subsequent reconciliation rather than assuming success. This is explicit and safer than silently claiming an atomic rollback that the remote API cannot guarantee.

## Follow-up diff assessment

`Reconcile` now checks caller cancellation before admitting each mutation, executes admitted mutations on a bounded detached context, and checks caller cancellation after completion. This prevents a canceled request from launching a not-yet-started write and prevents rollback from racing an in-flight write whose remote outcome is unknown. The existing cancellation/deadline regression remains passing.
